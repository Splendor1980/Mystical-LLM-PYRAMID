# Mystica — маленькая русскоязычная мистическая LLM (RWKV-5.2, 11M)

Генеративная языковая модель **11 030 000 параметров** на архитектуре
**RWKV-5.2 (Eagle)**, обученная с нуля на синтетике и отвечающая на вопросы о
мистике, эзотерике, рунах, снах, местах силы — **полностью офлайн**.

Ключевая идея проекта: «своя LLM» — это теперь **ночь на одной бесплатной T4
и файл весов 22 МБ**, который крутится на CPU обычного смартфона.

| Параметр | Значение |
|---|---|
| Параметров | 11.03M (13 слоёв, 256 hidden, 8 голов, head_size 32) |
| Контекст | 512 токенов |
| Словарь | 3000 BPE-токенов (NFKC + ByteLevel), эмбеддинг/head связаны |
| Веса обучения | fp32 (`ckpt_*.pt`) |
| Веса инференса | **fp16, `model.bin`, 22.2 МБ**, собственный формат `RWKV5` |
| Обучение | Kaggle NVIDIA T4, ≈6.4 ч, 22 179 итераций, ~16.3k ток/с |
| Качество | val-loss **0.1638** → **PPL ≈ 1.18** |
| Инференс | Java-порт, ~40 ток/с на телефоне, ~60–70 ток/с на ПК (JVM, fp16, 1 поток) |
| Совместимость | Python (PyTorch) + чистый Java без зависимостей + Android APK |

Формат диалога (как в обучении, без вопросительного знака — его нет в словаре):

```
Вопрос: {вопрос}
Ответ: {ответ}
```

## Быстрый старт

### Java / JVM (без Python)

```powershell
# собрать ядро + утилиты
javac -encoding UTF-8 -d build\classes (Get-ChildItem -Recurse java\core -Filter *.java | % FullName) java\tools\Gen.java
# генерация: файл модели, промпт, сид, температура, top-k, максимум новых токенов
java -Dfile.encoding=UTF-8 -cp build\classes Gen model\model.bin "Какой камень лучше всего подходит для защиты дома" 11 0.7 40 110
```

Проверка порта против эталонов — `PortCheck` (`java\tools\PortCheck.java`):
encode 30/30, decode 0 расхождений, рекуррентность maxAbs 6.2e-06.

### Python (PyTorch)

```bash
# обученные веса fp32 (для инференса/продолжения обучения)
python training/rwkv_model.py            # определение архитектуры
python training/gen_ref.py --ckpt model/ckpt_best.pt --tok tokenizer/tokenizer.json    # пример генерации
```

### Android

Сборка APK без Gradle — `android/build-apk.ps1` (нужен Android SDK 34 + JDK).
`model.bin` кладётся в `app/src/main/assets/`. Готовый релизный ключ и иконки —
в `release/` проекта (в репозиторий не входят, см. `.gitignore`).

## Структура репозитория

```
model/        model.bin (fp16, инференс), ckpt_best.pt / ckpt_last.pt (fp32, обучение), SHA-256
tokenizer/    tokenizer.json (BPE, vocab 3000)
training/     трейнер и экспорт (rwkv_model, train_mystic, kernel_main, export_app_model, …)
java/         зависимый от одного файла Java-порт (BinIO, Tokenizer, Rwkv, Generator) + утилиты
android/      приложение «Мистика» + Gradle-free сборка
```

## Обучение

| Фаза | Данные | Токенов | LR | Комментарий |
|---|---|---|---|---|
| A — претрейн | нарратив + Q&A (3.3%) | ≈227.19M | 2e-4 → 3e-5 | 1 эпоха |
| B — SFT | Q&A (4886 пар × 8) | ~22.6M | 5e-5 → 1e-5 | 3 эпохи |
| C — дошивка | 90% нарратив / 10% Q&A | 0.5 эпохи | — | чтобы не разучиться «легенде» |

Оптимизатор AdamW (0.9, 0.95), grad clip 1.0, weight decay только на 2D-матрицы,
bf16 autocast на T4, чекпойнты пушились в облако каждые ~20 минут.

**Корпуса не включены** (синтетика Sonnet/Grok; раздача зависит от их ToS) —
в папке `training` лежит весь код, воспроизводящий датасеты и запуск.

## Верификация порта

- Энкодирование: 30/30 батарея (кириллица, emoji, NFKC, UNK);
- Декодирование: 0 расхождений на всех 3000 id;
- Рекуррентность (14 токенов) maxAbs **6.2e-06** против fp16-эталона Python;
- Детерминированный e2e: одинаковый сид/temp/top-k → идентичный текст на ПК
  и на телефоне (хвост расходится только из-за FMA на ARM).

## Примеры (температура 0.7, top-k 40, до 120 новых токенов)

**Вопрос: Что символизирует руна Одал**

> Сон у места силы «Гёбекли-Тепе» значит, что вопрос уже ищет ритуал, а не новую
> справку. Посланцы народа в таком сне несут характер: подводные купола памяти
> и тихий закон океана. Само место…

**Око леса смотрит на тебя**

> Посылка: имя «Ванга» в этой школе держит почерк «бытовой знак и предостережение
> не путать страх с видением». Из живого образа не следует календарь. Поздние
> годы часто дописывает век, не зрение. Поэтому…

## Ограничения

- Узкий домен (мистика/эзотерика); **не** универсальный ассистент.
- В словаре нет `?` и части пунктуации — промпты без вопросительного знака.
- Любит устойчивые зачины и повторы (гуард от зацикливания в приложении —
  12 одинаковых токенов подряд).

## Честные итоги бенчмарка против «равных противников»

Эмпирический прогон 10 вопросов домена (seed 42, temp 0.7, top-k 40, ≤110 новых
токенов; у Qwen3 отключён режим «мышления», иначе весь лимит уходил на монолог)
против маленьких открытых моделей, которые реально ставится на те же устройства.
Скорость замерена на Intel Xeon E5-2650L v3 (12 ядер / 24 потока, 1.8 ГГц):

| Модель | Параметры | Файл | Скорость на этом ПК (CPU) |
|---|---|---|---|
| SmolLM2-135M-Instruct | 135M | 138 МБ (GGUF Q8_0) | ≈ 88 ток/с |
| Qwen3-0.6B-Instruct | 0.6B | 767 МБ (GGUF Q8_0) | ≈ 23 ток/с |
| TinyLlama-1.1B-Chat | 1.1B | 1116 МБ (GGUF Q8_0) | ≈ 14 ток/с |
| **Mystica (этот репозиторий)** | **11M** | **22 МБ fp16** | **≈ 60 ток/с** (JVM, 1 поток) |

> **Про «88 ток/с» у SmolLM2 при файле 138 МБ.** Размер файла ≠ стоимость
> вычислений: по математике на один токен 11M дешевле ~в 12 раз, чем 135M.
> Скорость измерена *как есть, двумя разными рантаймами*: соперники — llama.cpp
> v0.4.1/b11100 (C++, int8-ядра Q8_0, AVX2, 8 потоков), мы — однопоточный
> Java-порт (fp16, JVM, без SIMD). «Тяжёлый» SmolLM2 обгоняет нас по ток/с за счёт
> рантайма, а не модели; на равном RWKV-GGML-бэкенде 11M была бы заметно быстрее.

Оценки 1–5 по рубрикам «грамотность русского / мистический жанр / связность /
ответ по теме / польза в домене», сумма:

| Модель | RU | Жанр | Связ. | Тема | Польза | Σ |
|---|---|---|---|---|---|---|
| SmolLM2-135M | 1 | 1 | 1 | 1 | 0 | 4 |
| Qwen3-0.6B | 5 | 2 | 4 | 2 | 1 | 14 |
| TinyLlama-1.1B | 2 | 2 | 3 | 2 | 1 | 10 |
| **Mystica** | **5** | **5** | **4** | **2** | **2** | **18** |

Честная интерпретация, без прикрас:

- Выигрываем русским (обучены только на нём), мистическим жанром и физикой:
  22 МБ против 138–1116 МБ. По скорости в JVM (≈60 ток/с) мы быстрее Qwen3-0.6B
  и TinyLlama-1.1B на том же CPU, а SmolLM2 обгоняет нас только за счёт рантайма
  (llama.cpp, 8 потоков, против однопоточного Java — см. примечание выше).
- Соперники домен не тянут: для Qwen3 «место силы» — это «точка, где вектор силы
  действует на объект»; TinyLlama на «сон про чёрную кошку» ответила по-английски
  и буквально; SmolLM2 повторила сам вопрос. Qwen3 не дала ни одного ответа по сути
  домена: «число семь» → «это число 7», «зачем пирамиды» → «древние вулканические
  пирамиды в Херсоне или Гизе».
- Наши собственные артефакты (не прячем): на «камни для защиты дома» и «место
  силы» модель выдала идентичный текст про Вангу (q2 = q7), «руна одал» ушла в
  гадание на воске, а «число семь» — в практику с маятником. **11M знает жанр,
  а не энциклопедию.** Фактическую справку не даёт никто из четвёрки.
- Обрыв генерации на полуслове в прогоне — это лимит окна 110 токенов; в приложении
  текст доводится до стоп-токена `<eos>`.
- Вывод: маленькая специализированная модель выигрывает языком, жанром и скоростью,
  но факты — это ограничение размера и конструкции данных (жанр вместо факта),
  а не баг промпта.

Полные выводы всех прогонов можно воспроизвести: 10 вопросов лежат в
`training/bench_prompts.txt`, параметры генерации одинаковы для всех моделей —
они же упомянуты в карточке модели на Hugging Face.
